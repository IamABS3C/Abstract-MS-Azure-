# Design — Local env + Visual investigation cockpit for the AI-SOC notebook

**Date:** 2026-06-19
**Status:** Proposed (awaiting user review)
**Scope:** First end-to-end slice of a larger program. This spec covers (0) a dead-simple
local conda environment and (1) the **Visuals & reports** capability slice. Other slices
(Abstract tenant core, OSINT enrichment, external SIEM bridges) are sequenced in the
Roadmap section but are **out of scope for this spec** — each gets its own spec → plan →
build cycle.

---

## 1. Goal & context

Turn the existing AI-SOC demo notebook (`docs/threat-model/demo/soc_notebook.ipynb`,
generated by `build_notebook.py`) into the easiest-to-run, most interactive,
picture-perfect **visual investigation** experience, runnable locally with one command.

The visuals layer already exists but is **static**: matplotlib figures (`viz.py`),
zero-dependency branded SVG (`viz_svg.py`), an HTML incident report (`report.py`), and a
command-center page (`dashboard.py`). This slice makes the visuals genuinely interactive
(drag/zoom/hover/click), standards-aligned (MITRE ATT&CK Navigator), officially branded,
and driven by an in-notebook control panel — while preserving the zero-dep SVG path as a
no-install fallback.

### Decisions locked in (from brainstorming)
- **Environment:** Miniforge (conda-forge, free at any org size). `abstract-soc` env. ✅ installed.
- **First slice:** Visuals & reports.
- **Interactivity deps:** pyvis + plotly, with JS **bundled inline** for full offline use;
  `viz_svg.py` kept as the zero-install fallback.
- **Write-back safety:** **dry-run by default** — every live mutation previews the exact
  payload + diff and requires an explicit in-notebook confirm before hitting the tenant.
- **Next slice after this one:** Abstract tenant core.

### Non-goals (this slice)
- No OSINT, SIEM, or new Abstract write surfaces beyond the report → view/insight write-back
  that `report.py` already performs (now made dry-run-first).
- No served web app (Panel/Dash/Streamlit). Notebook-native only.
- No change to the detection/scoring engine (`pipeline.py`, `identities.py`, etc.).

---

## 2. Architecture

Additive, modular, follows existing file conventions (one module = one purpose, pure
functions, lazy imports of heavy libs, a `selftest()` per module).

```
                         brand.py  (single source of palette/fonts/logos)
                            │  consumed by every viz + report
        ┌───────────────────┼───────────────────────────────┐
   viz_svg.py           viz.py                         viz_interactive.py   (NEW)
   (zero-dep SVG,     (matplotlib,                     pyvis link graph + blast radius,
    fallback)          existing)                        plotly charts; inline-JS, offline
        │                  │                                   │
        └──────────────────┴───────────────────┬──────────────┘
                                                │
                       mitre_layer.py (NEW)     │     report.py (UPGRADED)
                       ATT&CK Navigator         │     self-contained branded HTML,
                       layer.json export        │     embeds interactive panels,
                                                │     dry-run write-back
                                                │
                                build_notebook.py (extended)
                                  └── "Visual investigation cockpit" section
                                      (ipywidgets control panel + panels)
                                                │
                                       soc_notebook.ipynb (regenerated)
```

**Degradation contract:** `viz_interactive.*` functions lazy-import pyvis/plotly. If
absent, they fall back to the matching `viz.py` (matplotlib) or `viz_svg.py` (SVG) output
so the notebook never hard-fails on a missing optional dep.

## 3. Components & interfaces

### 3.0 Environment & dead-simple run
- **`environment.yml`** (in `docs/threat-model/demo/`): pins the `abstract-soc` env —
  python 3.12, jupyterlab, ipykernel, ipywidgets, nbformat, nbconvert, matplotlib,
  networkx, numpy, pandas, plotly, requests, pyvis (conda-forge) + `mcp` (pip).
- **`run.sh`** (and a brief Windows note): one command that resolves the **trailing-space
  repo path** safely, activates `abstract-soc`, registers the Jupyter kernel if missing,
  and launches `jupyter lab soc_notebook.ipynb`. Idempotent; prints next steps on error.
- **README rewrite**: a "Quick start in 3 commands" block at the very top
  (`conda env create -f environment.yml` → `./run.sh`), with the existing venv path kept
  as an alternate.

### 3.1 `brand.py` (NEW — single source of truth)
- Exposes official palette: `PINK="#FF216B"`, `PINK_MID="#E8005D"`, `PINK_DEEP="#C2004C"`,
  `BG="#060608"`, `WHITE="#FFFFFF"`, `TEAL="#01e69d"`, `AMBER="#f5c61e"`, `BLUE="#2e9bf0"`,
  plus `INK`, `MUT`, `PANEL`, and the `TYPE_COLOR` entity map.
- Fonts: Barlow / Barlow Semi Condensed / JetBrains Mono. Font loading is **self-contained**
  (no Google-Fonts CDN) — system-font fallback stack; optional local font embed if assets exist.
- `logo_svg(variant)` returns the official Abstract logo markup from the memory assets
  (white/black lockups + mark per CLAUDE.md `reference-abstract-brand`).
- `viz.py` and `viz_svg.py` are refactored to import constants from `brand.py` (replacing
  the scattered, slightly-off `#f8226a`). No behavior change beyond the corrected pink.

### 3.2 `viz_interactive.py` (NEW)
Pure functions mirroring `viz.py` signatures; each returns embeddable HTML (str) or a
Plotly `Figure`. Lazy imports; offline-safe embedding (`include_plotlyjs="inline"` /
pyvis local assets).
- `link_graph(graph, iocs, scores, *, height="640px") -> html` — pyvis vis.js graph:
  drag, zoom, hover tooltips (entity kind, risk, last-seen), click highlights neighbors;
  node color by `brand.TYPE_COLOR`, size by risk. The Maltego-style pivot graph.
- `blast_radius(scoping) -> html` — interactive concentric/force view of patient-zero →
  real-time → replay rings.
- `risk_panel(scores) / timeline(events) / trajectories(scores) / coverage_by_rule(findings)
  / efficiency(metrics) / identity_taxonomy(counts)` — Plotly interactive versions of the
  existing matplotlib charts.
- `selftest()` — dep-free shape checks (string contains `<div`/`vis-network`, etc.), same
  style as `viz_svg.selftest()`.

### 3.3 `mitre_layer.py` (NEW)
- `build_layer(tactics, observed_techniques, name) -> dict` — ATT&CK Navigator layer schema
  (techniques scored by coverage + flagged where observed in the campaign).
- `write_layer(path="mitre_layer.json")` — artifact you can drag into the real Navigator.
- `matrix_html(tactics) -> html` — in-notebook interactive matrix (reuses `brand`).
- `selftest()` — validates layer JSON has required keys + at least one technique.

### 3.4 `report.py` (UPGRADED)
- New `html_report()` builds **one self-contained** branded HTML doc: official header/logo,
  executive summary, embedded `viz_interactive.link_graph` + blast radius + Plotly panels +
  KPI cards + narrative + MITRE matrix + recommended actions. Print-to-PDF clean
  (`@media print`). All JS inline → opens anywhere, no network.
- Write-back becomes **dry-run by default**: `--writeback` previews the exact field-set/view
  (and optional insight) payload + a diff vs. what exists, and requires `--apply` (CLI) or an
  explicit confirm widget (notebook) before any POST. Existing `[ABS-DEMO]` idempotent,
  self-cleaning behavior preserved.

### 3.5 Notebook integration (`build_notebook.py` extended)
- New section **"Visual investigation cockpit"**: an `ipywidgets` control panel
  (incident/entity picker, time-window, palette toggle, which panels to render, a
  **dry-run → confirm → apply** write-back control) that renders the `viz_interactive`
  panels + MITRE matrix inline and offers one-click export of the branded report + Navigator
  layer.
- Regenerate `soc_notebook.ipynb` from source; **re-validate** it executes end-to-end headless.

## 4. Data flow

1. Notebook builds the engine state (`normalize → Graph → run_detections →
   run_investigation → continuous_scores → efficiency`) — unchanged.
2. Control panel parameters select incident/entities/time-window/panels.
3. `viz_interactive` + `mitre_layer` render interactive panels inline using `brand`.
4. Export → self-contained branded HTML report + `mitre_layer.json`.
5. Optional write-back → **dry-run preview** (payload + diff) → explicit confirm → POST to
   Abstract as view/insight (reusing `abstract_client.py`).

---

## 5. Error handling
- **Missing optional dep** (pyvis/plotly): lazy-import guard → fall back to `viz.py` /
  `viz_svg.py` output with a one-line note. Never hard-fail.
- **Offline / no Abstract key**: notebook runs fully on the synthetic estate; live panels
  (MITRE coverage, write-back) show a clear "offline — using modeled data" badge.
- **Write-back**: dry-run is the default path; a live POST happens only after explicit
  confirm. Failures surface the HTTP status + body, never a raw token (AES/secret hygiene:
  keys read from env, never printed/logged).
- **Trailing-space repo path**: `run.sh` quotes all paths; `selftest`/nbconvert invoked via
  the env's kernel by name, not by absolute path interpolation.

## 6. Testing
- Each new/changed module keeps a `selftest()` (dep-free shape checks), runnable as
  `python <module>.py`.
- `build_notebook.py` regenerates the notebook; CI-style check executes it headless via
  `jupyter nbconvert --to notebook --execute --inplace --ExecutePreprocessor.kernel_name=abstract-soc`.
- Report HTML validated to be self-contained (no `http(s)://` asset refs) and to open with
  no console errors.
- Manual: open the notebook in the new env, drive the control panel, export the report,
  load `mitre_layer.json` in ATT&CK Navigator.
