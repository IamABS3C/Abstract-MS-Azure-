# Contributing

This repository is public and customers deploy straight from `main`, so every change goes
through a pull request and CI.

## What is generated, and from what

| Output | Generated by | From |
| --- | --- | --- |
| Deploy tables in `README.md`; template reference and template-spec sections in `solutions/README.md`; the logo in every portal wizard | `solutions/scripts/gen-deploy-links.py` | `solutions/solution.manifest.json` |
| The GitHub Pages deployment console, `docs/index.html` | `solutions/scripts/gen-pages.py` | the manifest |
| The Sentinel table schema, DCR transformation and portal sample (`all_fields.json`) | `solutions/scripts/gen-sentinel-schema.py` | the ACS field catalog, `solution/schema/acs-fields.json` |
| The ASIM dataflows in both Sentinel templates and their portal forms | `solutions/scripts/gen-sentinel-asim.py` | `solutions/asim/*.kql` and `solutions/asim/tables/*.json` |
| Every `*.azuredeploy.json` | `az bicep build` (or `validate-templates.py --fix`) | the `.bicep` beside it |
| README banner and logo PNGs | `solutions/brand/build.sh` | the official SVGs in `solutions/brand/` |

Never edit a generated file by hand; CI regenerates it with `--check` and fails on any
difference.

## Before you open a pull request

```bash
python3 solutions/scripts/validate-templates.py --fix   # recompile stale ARM, check every UI against its template
python3 solutions/scripts/gen-deploy-links.py --write   # README tables, template reference, portal logos
python3 solutions/scripts/gen-pages.py                  # deployment console
python3 solutions/scripts/gen-sentinel-schema.py        # only when the ACS catalog changes
python3 solutions/scripts/gen-sentinel-asim.py          # only when solutions/asim changes
python3 solutions/ci/json-lint.py .
bash solutions/ci/secrets-scan.sh .
```

CI (`.github/workflows/validate.yml`) runs all of these in `--check` mode, plus shell and
PowerShell parsing and an advisory ARM TTK run.

## Rules for this repository

- **No customer names, tenant IDs, subscription IDs, vault names or real user identities**
  in any file. Use placeholders such as `<vendor-account-id>`.
- **No secrets**, ever, including in examples.
- **Anything a template writes into a customer workspace** must be listed in
  `solutions/docs/sentinel-destination-assurance.md` (Sentinel) or the template's reference
  entry, and the "never touches" list must stay true.
- **Claims are tested, not inferred.** Mark anything you could not measure as not verified.
- Commit messages are imperative and one sentence.

## Customize it

Nothing here requires reading Bicep to change. In rough order of how often you will want it:

| I want to… | Edit | Then run |
| --- | --- | --- |
| Change hub names, partitions, retention, tiers | `parameters/*.parameters.json` | nothing — pass with `--parameters @file` |
| Change which log categories are collected | the wizard, or the `*Categories` parameter | nothing |
| Add/remove Graph permissions | `graphPermissions` parameter (names are validated at runtime) | nothing |
| Add a new template | `solution.manifest.json` → `templates[]` | `gen-deploy-links.py --write` and `gen-pages.py` |
| Change branding or copy on the deployment console | `solutions/scripts/gen-pages.py` | `gen-pages.py` |
| Rename or move the repo | `solution.manifest.json` → `repo` | `gen-deploy-links.py --write` and `gen-pages.py` |
| Change template logic | the `.bicep` | `az bicep build …` then `validate-templates.py` |

**Guardrails while you edit:**

```bash
python3 solutions/scripts/validate-templates.py          # contract check
python3 solutions/scripts/validate-templates.py --fix    # also recompile stale ARM
python3 solutions/scripts/gen-deploy-links.py --check    # are the buttons current?
```

The validator catches what `az bicep build` cannot: a UI output that is not a template
parameter, a required parameter the UI never supplies, a broken `steps()` reference, and a
UI model that cannot bind to the template's scope. It found a real shipped bug the first
time it ran — a management-group template with a `createUiDefinition`, which can never work.

## Port it to another repo

This directory is self-contained and designed to be lifted out:

```bash
# 1. Copy the solution into the new repo
cp -r solutions/ /path/to/new-repo/

# 2. Point the manifest at the new home — this is the ONLY place repo coords live
#    Edit solutions/solution.manifest.json → "repo": { owner, name, branch }

# 3. Regenerate every button, table, portal logo and the console
cd /path/to/new-repo && python3 solutions/scripts/gen-deploy-links.py --write && python3 solutions/scripts/gen-pages.py

# 4. Prove it
python3 solutions/scripts/validate-templates.py
```

No other file contains the repo owner, name or branch. That is enforced by CI:
`gen-deploy-links.py --check` fails if any generated region is stale.

**One caveat:** Deploy-to-Azure buttons need the raw template URLs to be **publicly
readable**. A private repo will render buttons that 404. Use the CLI or template-spec
paths there, or publish the templates to a public location.
